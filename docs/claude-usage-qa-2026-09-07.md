# Claude 使用量の取得調査（2026-09-07）

## 確認した事実

- 本家 Issue #5（https://github.com/vinzdg/codenotch/issues/5）は重複キーチェーン項目から古いものを選ぶ問題。v1.4.0で修正済みで、このフォークにも含まれる。
- 調査開始時、既定の Claude Code キーチェーンは1件のみ。保存された有効期限は9月7日01:06 JST。実アプリのログは credentialExpired だった。これは保存済みトークンの状態であり、ターミナルやデスクトップのClaude全体が利用不能という証拠ではない。
- 21:32頃に同じ保存先のトークンが更新された。その後、同じ使用量APIへの読み取りがHTTP 200となった。調査側でログアウト、再ログイン、トークンの書き換えは行っていない。更新を起こしたプロセスは特定していない。
- 実アプリは再起動前に自動復帰。21:34 JSTの保存済み使用量はセッション0%、週38%。アクセシビリティでもClaudeのリング0%を確認。
- 保存済みトークンが更新されるまで古かった理由は未特定。Claude Code側のキーチェーン永続化問題の報告（https://github.com/anthropics/claude-code/issues/19456）はあるが、今回と同一原因とは断定できない。

## 修正と検証

- 初回取得が失敗したstale状態を「最初のデータを取得しています」と表示する不具合を修正。更新待ちや一時的な取得制限の可能性、および自動再試行を明示する。
- 本当に初回取得中の状態は従来の文言を維持。再ログインを要求せず、取得済み数値の保持と既存のバックオフを維持。
- 認証期限・レート制限の双方で誤った取得中表示やサインイン要求に戻らない回帰テストを追加。
