# 日本語版で本家の更新を取り込む方法

本家の更新を利用することは可能です。ただし、本家が配布する `.app` で日本語版を直接置き換えると、日本語化・四隅の配置・独自の修正が失われます。

想定する構成は次のとおりです。

1. 本家のタグやコミットの更新を検知する。
2. フォークへの取り込みブランチを作り、変更をマージする。
3. 日本語の表示、新規の英語文言、独自機能への影響を確認し、ビルド・テストする。
4. 日本語版をビルドし、日本語版専用の鍵で更新アーカイブに署名する。
5. 日本語版の更新フィードと配布ファイルを公開し、アプリがそのフィードから更新する。

本家の変更が翻訳や独自機能と競合した場合は、その時点で確認が必要です。「更新の検知・取り込み候補の作成」と「テスト済みアプリの配布・インストール」は別の工程です。

Sparkle では日本語版専用の `SUFeedURL`、`SUPublicEDKey`、増加するビルド番号を設定します。署名用秘密鍵をソース管理に置かず、配布用の署名設定を用意する必要があります。Developer ID 署名・公証を使う構成が推奨されています。

出典：[Sparkle 公式ドキュメント](https://sparkle-project.org/documentation/)

現時点では構成案です。自動取り込みのジョブ、署名鍵、配布フィードは未設定で、アプリ内の自動更新は引き続き無効です。
